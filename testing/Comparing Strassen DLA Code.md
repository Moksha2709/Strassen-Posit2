Pogue and Nicola Nicolici). 

Instead, the code in this workspace is a **custom research extension** that implements a **Posit-based** Strassen accelerator. It is designed to benchmark its performance and resource utilization against the paper's original architectures (as seen in scripts like [simulate_paper_tables.py](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/8_bit_posit_7_array_triple/simulate_paper_tables.py)).

Here is a breakdown of the key differences:

### 1. Source Repository & Author Origin
* **The Paper's Code:** The original open-source code cited in the paper is hosted in the [trevorpogue/algebraic-nnhw](https://github.com/trevorpogue/algebraic-nnhw) repository on GitHub.
* **Local Workspace Code:** The code in [strassen_dla](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla) is a customized implementation tailored for Posit-based compute verification (frequently evaluated using co-simulation workloads, as outlined in [rtl_integration_guide.md](file:///c:/SRIP2/8_bit_posit_strassen_paper/rtl_integration_guide.md)).

### 2. Arithmetic & Data Formats
* **The Paper's Code:** Focuses exclusively on **fixed-point** (e.g., 16-bit integer/fixed-point) representations. 
* **Local Workspace Code:** Implements **16-bit Posit arithmetic** (`POSIT_WIDTH = 16`, `POSIT_ES = 1`) defined in [posit_pkg.vh](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/posit_pkg.vh). It contains custom Posit hardware components such as `posit_add`, `posit_mult`, `posit_decode`, `posit_encode`, and a `quire_acc` accumulator.

### 3. Implementation Language & File Structure
* **The Paper's Code:** Written in **SystemVerilog** (files ending in `.sv` and `.svh`, such as `define.svh`, `pkg.sv`, `mxu.sv`, and `mac_array.sv`).
* **Local Workspace Code:** Written in standard **Verilog** (files ending in `.v` and `.vh`, such as [strassen_top.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/strassen_top.v), [strassen_controller.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/strassen_controller.v), [strassen_preprocess.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/strassen_preprocess.v), and [strassen_scratchpad.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/strassen_scratchpad.v)).

### 4. Hardware Architecture
* **The Paper's Code:** Proposes a "Multisystolic Array" where a larger physical systolic array is logically partitioned or combined to execute different sub-matrix multiplications of Strassen's algorithm in parallel.
* **Local Workspace Code:** Uses a looping sequential design that performs 16x16 matrix multiplication by reusing a **single** 8x8 systolic array over time, orchestrated by the state machine in [strassen_controller.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/strassen_controller.v) and the BRAM-based scratchpad in [strassen_scratchpad.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/strassen_scratchpad.v).
* *(Note: The adjacent directory [8_bit_posit_7_array_triple](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/8_bit_posit_7_array_triple) contains another design variant that uses 7 parallel systolic arrays combined with "triple-packing" arithmetic, which is described in [Explaining_Triple_Packed_Posit_Strassen_Accelerator.md](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/8_bit_posit_7_array_triple/Explaining_Triple_Packed_Posit_Strassen_Accelerator.md)).*

### 5. Verification Framework
* **The Paper's Code:** Uses a Python-based **cocotb** testing environment alongside a **UVM** (Universal Verification Methodology) testbench.
* **Local Workspace Code:** Employs standard Verilog testbenches (`eval_tb.v`) compiled via Icarus Verilog (`iverilog` / `vvp`), with overall metrics driven by custom Python scripts like `eval_accuracy.py` and `eval_medical_imaging.py`.

### 2. Required Arithmetic and Timing Bug Fixes
To ensure correct arithmetic decoding, timing convergence, and simulation accuracy in your DLA code, you need to apply the following fixes (already present in the upgraded SIMD directory):

#### A. Direct Leading-Zero Detector (LZD) in [posit_to_fixed_conv.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/16_bit_posit_one_systolic/posit_to_fixed_conv.v)
*   **Problem**: In lower bitwidth modes (like 12-bit), parsing the regime run-length by splitting and tapping into separate high/low slices fails for negative numbers due to two's complement carry bits.
*   **Change**: Replace split sub-word taps with an independent, direct 11-bit Leading Zero Detector for the absolute value of the decoded bus.

#### B. PE Accumulator Draining Delay in [strassen_controller.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/16_bit_posit_one_systolic/strassen_controller.v)
*   **Problem**: The controller FSM registers the PE values one cycle too early before all pipelined products from the PE grid settle in the accumulator registers, resulting in corrupted output values.
*   **Change**: Extend the FSM's `RUN_SYSTOLIC` counter state duration by 3 cycles (from `SZI + 2*SZJ + 1` to `SZI + 2*SZJ + 4`). This allows the pipelined multipliers to drain completely and settle into the accumulators before the capture signal fires.

#### C. Explicit Signed Declarations in [posit_pe.v](file:///c:/SRIP2/8_bit_posit_strassen_paper/8_bit_posit_strassen/strassen_dla/16_bit_posit_one_systolic/posit_pe.v)
*   **Problem**: Simulators and synthesizers can sign-extend intermediate logic values incorrectly when multiplying slices of a wide decoded bus.
*   **Change**: Explicitly declare intermediate buses as `signed` when passing them into multiplier arithmetic paths inside your PEs.
